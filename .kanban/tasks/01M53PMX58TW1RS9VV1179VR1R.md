title: A second held URL flow under the same wire id sends an accept for the earlier flow with no completion
---
Found during ^etqn9dn.

In MCPServer+Elicitation.swift, `awaitHostCompletion(of:)` holds the URL-mode accept of the host handler. When a second flow opens under a wire id that is still held, the function resumes the earlier continuation with `nil`. `nil` means "the flow completed", thus the earlier flow sends ACCEPT to the server, but its completion never came.

Decide the correct answer for the earlier flow. A possible answer: a cancel with a reason in `_meta` (for example "a newer URL flow used the same elicitation id"), through the same `wireResult(of:)` path as `connectionEndedReason`.

Start with a fixed-order test that fails on the current code: two URL flows of the handler under one wire id, and the test reads the result of the first flow on the wire. No time limit, sleep, poll or retry. #elicitation-fixes
