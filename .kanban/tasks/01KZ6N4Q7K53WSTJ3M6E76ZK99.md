Repo: this repo. Basis: eventplan.md §"The sandbox globals" and the capability-contract table.

## What
Add six top-level globals to the snippet sandbox (installed the way `help`/`docs` are, in `MultiTool.makeHelpDocsHostFunctions`-style factories in `MultiTool.swift`):
- `status(completionToken?)` — promise; with a token, that run's lifecycle; with no argument, lists each pending run from the session mailbox: token, op, latest progress. Run plane only — never bulk output.
- `wait(completionToken, seconds)` — promise; awaits settlement via the mailbox with a deadline. Returns the terminal event's `detail` — the capped output tail plus the run's identifier (the single `wait()` contract fixed in the SessionMailbox task) — never a capability's full store.
- `cancel(completionToken)` — promise; invokes the honest canceler, returns the honest outcome.
- `elicit(request)` — promise; parks through `ToolContext.elicit` on the ambient context (same elevation path as every other call; the model itself can stop mid-snippet for a user answer). String shorthand `elicit("question")` maps to a form-mode message-only request.
- `notify(detail)` / `progress(detail)` — synchronous, void: enqueue through `ToolContext.post`/`progress` and continue; the bridge flushes them. The outbox coalesces snippet `progress()` like any tool's progress event.
- The one-rule contract holds: calls that do Swift effects return promises (`tools.*`, `elicit`, `wait`, `status`, `cancel`); `help()`/`docs()` stay sync reads; `notify()`/`progress()` are sync void.
- No-ambient-context degradation (a `MultiTool` constructed and called directly, outside any Router session — exactly how the existing unit suites run): the four promise-returning run-plane globals (`status`, `wait`, `cancel`, `elicit`) reject with a precise, named, model-repairable error ("no session context — this run has no run plane") and never trap; `notify`/`progress` are silent no-ops (consistent with nil-context `post`).
