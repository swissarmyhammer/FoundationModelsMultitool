## What
The user decision on ^tm4x2hp and ^kdtrmhv is: "no test checks the speed of the machine". The `JSCInterpreter` watchdog has no clock seam. Thus these tests still depend on a real watchdog time:

- `Tests/FoundationModelsMultitoolTests/HardeningTests.swift` `executionTimeLimitBoundaryAllowsAFastSnippet`: a 0.3 s watchdog must not fire. A slow machine can make it fire.
- `HardeningTests.cancellationStressTestNoDeadlock`: a 10 s watchdog.
- About 45 tests that use the default 5 s watchdog of `JSCInterpreter`. A slow machine can end a snippet that is correct.
- The dry-run time limits in `SampleSnippetTests`, `SearchToolsToolTests` and `MCPCapabilityTests`.

^kdtrmhv used `unreachedTimeLimit` (86_400 s) for the tests that it changed. That is a stopgap, not a seam.

## Do
- Add an injected clock (or an event seam) for the watchdog of `JSCInterpreter`. The production default stays the real clock.
- Convert each test above: a test of the watchdog opens the clock. Every other test uses a clock that does not end.

## Acceptance Criteria
- [ ] No root test depends on the real time of the watchdog.
- [ ] The watchdog tests prove the watchdog fires, by an event, not by a duration.

## Tests
- [ ] Root `swift test` passes once.
