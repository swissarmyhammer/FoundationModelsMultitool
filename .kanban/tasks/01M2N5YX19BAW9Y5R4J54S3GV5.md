## What

In `Sources/FoundationModelsMultitool/Surface/ToolAPIRenderer.swift`, three example and declaration builders put schema-derived text between double quotes with `escapeForJSStringLiteral(_:)`, which escapes a backslash and a double quote only:

- `objectKeyLiteral(_:)` for a property name that is not a bare identifier,
- `tsLiteral(_:)` for a string enum choice,
- the `.string` placeholder in `exampleLiteral(for:name:context:)` and `exampleLiteral(for:name:)`.

A raw line feed, carriage return, U+2028 or U+2029 in that text stays raw inside the quotes. JavaScript refuses a raw line feed or carriage return inside a string literal, so the `@example` call and the `declare function` object type do not parse. A `@Generable` struct cannot produce such a name, but a hand-built `DynamicGenerationSchema` or a typed `RenderedParameter` can.

`jsStringLiteral(_:)` in the same file already escapes all four line terminators.

## Changes

1. Route the three builders through `jsStringLiteral(_:)`.
2. Add one test per builder in `Tests/FoundationModelsMultitoolTests/ToolAPIRendererTests.swift` with a name or a choice that holds a raw line feed. Assert the rendered text holds the escape `\n` and no raw line feed.
3. Keep every golden in `Tests/FoundationModelsMultitoolTests/Goldens` unchanged.

## Acceptance Criteria

- [x] A property name with a raw line feed renders as a quoted key with `\n` in the declaration and in the example.
- [x] A string enum choice with a raw line feed renders with `\n` in the declaration, the `@param` clause and the example.
- [x] `swift test --filter ToolAPIRendererTests` passes.
