## What
Add the provider seam and the ordered fallback. Design: `web.md` § "Providers and API keys" (the adapter protocol) and § "Fallback".

- Create `Sources/FoundationModelsMultitool/Capabilities/Web/Providers/SearchProviderAdapter.swift`:
  - `protocol SearchProviderAdapter: Sendable { var name: String { get }; var supports: Set<SearchFeature> { get }; var isHostConfiguration: Bool { get }; func request(for query: SearchQuery, key: String?) throws -> URLRequest; func parse(_ data: Data, response: HTTPURLResponse) throws(ProviderFailure) -> [WebHit] }`. `isHostConfiguration` defaults to `false`; only SearXNG sets it.
  - `SearchFeature`: `.freshness`, `.site`, `.count`. `SearchQuery`: `text`, `count`, `freshness`, `site`. `WebHit`: `rank`, `title`, `url`, `snippet`. `ProviderFailure`: `.badKey`, `.rateLimited`, `.serverError(Int)`, `.challenge`, `.noResults`, `.parse(String)`.
- Create `Sources/FoundationModelsMultitool/Capabilities/Web/WebSearchChain.swift`:
  - `struct WebSearchChain` made from `[(WebSearchProvider, any SearchProviderAdapter)]`, a `WebFetcher`, and the environment dictionary.
  - `func search(_ query: SearchQuery) async -> SearchOutcome` (provider name, hits, notes) or a correction.
  - Send each provider request with `WebFetcher.load(_:timeout:guarded:)`, with `guarded: !adapter.isHostConfiguration`.
  - Try providers in order. Skip to the next provider on: a key variable that is not set now, 401/403, 429, 5xx, a challenge, no results, a timeout, a guard refusal. Each skip adds one note, for example `braveAPI: skipped, BRAVE_SEARCH_API_KEY is not set.`
  - A query field that the selected provider does not support adds a note, for example `freshness is not supported by duckDuckGoHTML and was ignored.`
  - When all providers fail: one correction that names each provider and its failure, for example `No search provider gave results. braveHTML: blocked (HTTP 429). duckDuckGoHTML: no results.`
  - Send each note and the correction through `redactingKeys` with the key values of this call.

## Acceptance Criteria
- [ ] Each failure kind goes to the next provider and adds exactly one note.
- [ ] The first provider that gives hits wins, and later providers get no request.
- [ ] When all fail, the correction names each provider in order.
- [ ] A provider error that echoes the key shows `<redacted>` in the note.
- [ ] When all providers fail and one error text echoes the key, the correction shows `<redacted>` and not the key.

## Tests
