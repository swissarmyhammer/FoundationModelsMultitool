## What
Make the MCP capability and its Builder short form. eventplan.md § "The capability contract": "The modules are opt-in: `withShell()`, `withFiles()`, and `withMCP(servers:)`." And § "Consolidation of the siblings": "Each connected server registers as its own top-level group: `tools.github.createIssue`, never `tools.mcp.github.createIssue`. The model must not see the transport."

- Modify `Sources/FoundationModelsMultitool/Capabilities/MCP/MCPCapability.swift` (the header exists from the first task): `public struct MCPCapability: Capability`. `noun` is the server's `ServerIdentity.name`. `tools` is one `MCPTool` per `MCPCatalogEntry` of the server's current catalog. `init(server: MCPServer) async throws` awaits `waitUntilReady()` and reads the catalog. One capability per server; `withMCP(servers:)` makes one for each.
- Modify `Sources/FoundationModelsMultitool/Surface/MultiToolBuilder.swift`: add `public func withMCP(servers: [MCPServer]) async throws -> Self`, next to `withShell` and `withFiles`, with the same doc comment style. It calls `withCapability(MCPCapability(server:))` for each server, in order. eventplan.md: "Servers connect before `buildRegistry()`." The method awaits readiness; it does not connect. A server that never reaches `.ready` throws `MCPServerError.notReady`.
- The duplicate-noun rule needs no new code: `withCapability` claims the noun, and `buildRegistry()` raises `MultiToolBuilderError.Kind.duplicateNoun`. eventplan.md: "An MCP server with the name `files`, against the files capability, fails loudly at `buildRegistry()`." Add the test.
- **The journal `op`.** eventplan.md § "Registration of capabilities": "`OperationEvent.op` stays the canonical `"verb noun"` string. Registration derives it as `"\(verb) \(noun)"`." Registration already does this for shell (`RegisteredJournalOpTests.swift` pins phase 2). Pin it for an MCP verb.
- Each entry of `findAPIs` needs a sample snippet (`Discovery/SampleSnippet.swift`). Check that the generic sample generator gives a correct call for a converted schema; if a case renders wrong, correct the generator, not the entry.
- Update `README.md` with a `withMCP` example next to the shell and files examples.

## Acceptance Criteria
- [ ] `MultiTool.Builder().withMCP(servers: [server]).build()` renders `tools.<serverName>.<toolName>` for each server tool, and no `tools.mcp` group exists.
- [ ] A snippet `await tools.<serverName>.echo({...})` reaches the loopback server and returns the rendered result — over the in-memory transport AND over the in-process HTTP loopback.
- [ ] `ToolContext.op` / `BackgroundRun.op` for a call of `tools.<serverName>.echo` reads `"echo <serverName>"`.
- [ ] `findAPIs` finds the server tools with the same ranking path as the built-in verbs, and each result has a sample snippet that runs.
- [ ] A server named `files` with `withFiles(root:)` present fails at `buildRegistry()` with `MultiToolBuilderError.Kind.duplicateNoun`.
- [ ] `swift build` succeeds.
