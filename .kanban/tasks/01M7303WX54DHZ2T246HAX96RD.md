## What
The MT-15 requirement: a test makes a registry in `sandboxed` mode and confirms that no capability starts a process.

Research: only two code paths in `Sources` start a child process: `ShellRunner` (`Subprocess.run`) and `StdioServerProcess` (`posix_spawn`). Each child is recorded in `ProcessRegistry.global` and in `ProcessLedger` (`Capabilities/ProcessLedger.swift`). `ProcessRegistry.global` is global, and other tests start processes in parallel, so a count of global children is not stable. Do NOT count PIDs and do NOT wait for a time.

New `Tests/FoundationModelsMultitoolTests/SandboxedRegistryNoProcessTests.swift`, structural checks:
- Make a `sandboxed` registry with every capability that `sandboxed` mode permits: `withFiles`, `withGit`, snapshots, `withEnvironment`, `withWeb` (with a stub search backend, no network), and an `MCPServer` on an in-memory transport.
- Confirm that no registered capability is a `ShellCapability` and that the noun list has no `shell`.
- Confirm that the `MCPServerPool` of the builder has no `StdioServerProcess`.
- Add a per-registry spawn hook if necessary: an internal `spawnObserver` (a closure that `ShellRunner` and `StdioServerProcess` call before each spawn, given through the builder, default nil). Run one `runCode` snippet that calls one read verb of each noun (for example `files.read`, `git.status`, `environment.get`) and confirm that the observer of this registry got zero calls. The observer is per registry, thus parallel tests do not change the result.
