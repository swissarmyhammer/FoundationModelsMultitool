    ### Card text for the FoundationModelsRouter board

    **Title:** LiveEmbeddingContainer.embed: pool with the padding mask, so a batch vector is the vector of its own text

    ## What
    `LiveEmbeddingContainer.embed(texts:in:)` (`Sources/FoundationModelsRouter/Resolution/LiveModelLoader.swift:805-830`) embeds a batch as one padded tensor. It right-pads each row with `tokenizer.eosTokenId`, gives `mask` to the model, and then calls `context.pooling(output, normalize: true, applyLayerNorm: true)` with no mask. For a `.last` pooling model (Qwen3 embedders, `mlx-swift-lm Libraries/MLXEmbedders/Models/Qwen3.swift:320`), `Pooling.callAsFunction` (`Libraries/MLXEmbedders/Pooling.swift:170-179`) finds the last token from the mask, and with no mask it takes the last PADDED position. Thus every row that is shorter than the longest row gets the hidden state of a pad token, and the vector depends on the pad count, not on the text. `.mean` and `.max` pooling have the same defect, because they also average or take the max over the pad positions.

    Measured on 2026-09-28 in FoundationModelsMultitool with `mlx-community/Qwen3-Embedding-0.6B-4bit-DWQ`: for a batch of 9 tool blocks (1498-2916 chars), the cosine between the batch vector and the vector of the same text embedded alone is 0.56-0.77 for the 8 shorter rows and 1.00 for the longest row. The longest row then wins the cosine signal for almost every query. A one-sentence edit of one row changes its rank because it changes its pad count.

    A second, smaller defect in the same function: the mask is `padded .!= eosTokenId`, thus a real EOS token that the tokenizer adds at the end of a text is also masked out. Build the mask from the token count of each row instead.

    ## Acceptance Criteria
    - [ ] `embed(texts:in:)` builds the mask from the token count of each row (1 for the real tokens, 0 for the pad), and gives it to the model AND to `context.pooling(output, mask: mask, normalize: true, applyLayerNorm: true)`.
    - [ ] For each text, the vector from a batch equals the vector from a batch of one, to float tolerance (cosine >= 0.999), for texts of different lengths.

    ## Tests
    - [ ] A gated real-model test: embed 3 texts of clearly different lengths as one batch and one at a time; expect cosine >= 0.999 for each pair. Today it gives about 0.6 for the shorter rows.
    - [ ] A unit test over the mask builder: rows of token counts [3, 5] padded to 5 give the mask [[1,1,1,0,0],[1,1,1,1,1]], and a row that ends with the EOS id keeps that position at 1.

    ## Consumer
    FoundationModelsMultitool task ^hd8266a (`UnknownToolHintLiveTests`) waits for this fix. Its catalog cosine signal is a padding artifact until then.
