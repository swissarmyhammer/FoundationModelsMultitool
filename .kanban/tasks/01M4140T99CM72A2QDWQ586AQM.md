## What
Rule (decision of the user): the only timeout is the outer `runCode` tool timeout (`MultiTool.timeout(from:)`). No clock is under it, also not a clock that selects a provider. The web verbs run as inner `tools.web.*` calls, so they get no clock of their own.

Remove these three clocks:
- [ ] **Fetch timeout.** Remove the `timeout` argument of `tools.web.fetch` (range 1…120 in `Sources/FoundationModelsMultitool/Capabilities/Web/Fetch.swift`, and its `@Guide` text "Omit it for 30"). Remove `WebFetchPolicy.defaultFetchTimeout` (`Sources/FoundationModelsMultitool/Capabilities/Web/WebConfiguration.swift`). Remove the timeout race in `WebFetcher.load(_:timeout:guarded:)` (`Sources/FoundationModelsMultitool/Capabilities/Web/WebFetcher.swift`) and the `WebFetchFailure.timeout` case if nothing else produces it.
- [ ] **Search timeout for each provider.** Remove `searchTimeout` from `WebFetchPolicy` and its use in `Sources/FoundationModelsMultitool/Capabilities/Web/WebSearchChain.swift` (near line 101). The chain goes to the next provider only when a provider fails or blocks, not on time.
- [ ] **URLRequest timeout.** URLSession always applies a request timeout (default 60 s) and a resource timeout. In `WebFetcher.prepare(_:timeout:)`, set `timeoutInterval` so that it never fires before the `runCode` timeout (for example `.infinity` or `TimeInterval.greatestFiniteMagnitude`; check what URLSession accepts). Check the `URLSessionConfiguration` that the fetcher uses and set `timeoutIntervalForRequest` and `timeoutIntervalForResource` the same way. Cancellation of the outer run cancels the data task.
- [ ] Update the web unit tests: `Tests/FoundationModelsMultitoolTests/WebVerbArgumentTests.swift` (`fetchSchemaBoundsTimeout`) and each fetch/search timeout test (find them with `rg -n -i "timeout" Tests/FoundationModelsMultitoolTests/Web*`). Remove the tests that test only a removed clock.

## Acceptance Criteria
- [ ] The `fetch` schema has no `timeout` field.

- [ ] No web code path calls `clock.sleep` or `Task.sleep` to bound a request.
- [ ] A fetch whose server never answers inside a mounted `runCode` ends when the `runCode` timeout fires, with the outer `.timedOut` outcome.
