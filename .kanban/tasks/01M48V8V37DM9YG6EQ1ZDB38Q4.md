## Goal

Port the `get changes` operation of the sah MCP tool `git` (git.md, "Layer 1", item 1).

## Source

- `../swissarmyhammer/crates/swissarmyhammer-tools/src/mcp/tools/git/changes/mod.rs`: `execute` (line 289-437) and `get_uncommitted_changes` (67). Its tests (line 440 and later) are the list of cases to port.
- `swissarmyhammer-git/src/operations.rs`: `find_merge_target_for_issue` (706-950), `get_changed_files_from_parent` (152), `get_changed_files_from_range` (188).

## Work

1. `Changes` verb (`name = "changes"`). Arguments: `branch: String?` (default: the current branch), `range: String?` (for example `HEAD~1..HEAD` or `HEAD~3`).
2. Result: `branch`, `parentBranch: String?`, `range: String?`, `files: [String]` (relative to the root, sorted, no duplicates), `correction: String?`.
3. Keep the rules of the source, in this order:
   - `range` is set: the files of that range. A bad range is a `correction`.
   - The branch has a parent (the merge target is not the branch itself): the files changed since the merge-base with the parent.
   - No parent and a clean tree: the range `HEAD~1..HEAD`. If that range fails (one commit only), an empty list and `range == nil`, with no correction.
   - No parent and a dirty tree: the uncommitted files only.
   - In all cases, add the uncommitted files (staged, unstaged, renamed, untracked). Reuse the status code of `tools.git.status`.
4. Port `find_merge_target_for_issue` exactly. Write the rules it uses in the doc comment.
5. Add the verb to `GitCapability.tools`.

## Tests

Port each test of `changes/mod.rs` that applies, and add:
- feature branch with commits and uncommitted files,
- main with a clean tree (last commit), main with one commit only,
- explicit range, bad range (correction), unknown branch (correction),
- root in a subfolder.
