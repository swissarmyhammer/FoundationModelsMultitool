## What
The second half of rebuild-and-swap. eventplan.md § "Consolidation of the siblings": "Then MultiTool swaps it in atomically at the next turn boundary — the same boundary where the outbox folds in events. Nothing changes below a snippet that runs. An in-flight run keeps the registry that it started with."

Router supplies the boundary through `TurnBoundaryTool.turnWillBegin()` (Router task `01M112SF3QTAYXEPRWNW77K41M`; stub `980b1w6` here). This task makes `MultiTool` conform and apply a staged registry there.

- Add `Sources/FoundationModelsMultitool/RegistryBundle.swift`: today `registry`, `hostFunctions`, `liveTools`, `preamble`, and `hintSearcher` are `let`s set in `MultiTool.init`. Group them into one `RegistryBundle` value built from a `Registry` in one function.
- Add `Sources/FoundationModelsMultitool/RegistryHolder.swift`: a `final class RegistryHolder: Sendable` (a reference box; `Mutex` from Synchronization is `~Copyable`, and `MultiTool` is a copyable struct, so the lock lives in the box, not in the struct). It holds the current bundle and the newest staged registry. `stage(_:)` keeps only the newest. `applyStaged()` moves the staged registry into the current bundle.
- Modify `Sources/FoundationModelsMultitool/MultiTool.swift`: `MultiTool` holds one `RegistryHolder` and reads `holder.current` one time at the start of `call(arguments:)`. The run keeps that bundle to its end. `public func stage(_ registry: Registry)` forwards to the holder (non-mutating; the box mutates).
- Add `MultiTool+TurnBoundary.swift`: `extension MultiTool: TurnBoundaryTool` with `turnWillBegin()` → `holder.applyStaged()`.
- **Forks share the holder by identity.** `MultiTool+Forking.swift` takes the blanket `forked()` that returns `self`, and its doc comment argues for that. Keep it. A fork copies the struct, which copies the reference to the same box, thus a fork and its parent swap together at the same tick. Add two sentences to that file's doc comment: the registry now changes only at a turn boundary; a run keeps the one it started with; forks share the box.
- **`SearchToolsTool` swaps with the same box.** It reads `registry.surface.entries` for selection. Give it the holder too, so `tools.searchTools` and the mounted `findAPIs` see the same registry as `runCode` at the same tick.
- **`Registry.makeSessionTools(...)` keeps its signature** (`[any FoundationModels.Tool]`). Its callers are `Sources/MultitoolCLI/CLIRunner.swift:467`, `IntegrationTests/Tests/FoundationModelsMultitoolIntegrationTests/Support/ScenarioRunner.swift:753`, `.../Support/ShellBackgroundRunner.swift:217`, and `Tests/FoundationModelsMultitoolTests/MultiToolExecutionTests.swift:345,359,372`; none of them changes. Add a second method, `makeSessionTools(...) -> (tools: [any Tool], staging: any RegistryStaging)`, where `RegistryStaging` is a small protocol with `stage(_:)`, for the refresher task. The old method calls the new one and drops the second value.
- The parked runs and the mailbox are untouched: the mailbox has session scope in Router.
